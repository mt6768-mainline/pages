Before wiping Android, take a full partition backup and extract all hardware details from the stock. Reflashing stock Android later just to check I2C devices is painful.

== UART
On some boards, such as Xiaomi Redmi Note 9, pads are labeled and easy to solder. On others, you may need to find UART, remove metal shields or even solder SMD resistors to get the output.

TIP: Once you have working UART, capture and save the boot log. It can be helpful for stock bootloader reverse engineering.

== Backup

There have been cases where IMEI was lost while testing mainline kernel. Back up every partition (except `userdata` and `metadata`) *before* flashing anything.

[,shell]
----
sudo -E ./mtk.py printgpt

# dumps metadata and userdata too
sudo -E ./mtk.py rl backup-dir/

# or at least these
sudo -E ./mtk.py r nvram backup-dir/nvram.img
sudo -E ./mtk.py r nvdata backup-dir/nvdata.img
sudo -E ./mtk.py r nvcfg backup-dir/nvcfg.img
sudo -E ./mtk.py r boot backup-dir/boot.img
sudo -E ./mtk.py r dtbo backup-dir/dtbo.img
sudo -E ./mtk.py r lk backup-dir/lk.img
sudo -E ./mtk.py r tee1 backup-dir/tee1.img
sudo -E ./mtk.py r persist backup-dir/persist.img
sudo -E ./mtk.py r protect backup-dir/protect.img
sudo -E ./mtk.py r proinfo backup-dir/proinfo.img
----

== Dump from stock
* Dump `/sys/firmware/fdt`, pull to the host and decompile. It has all overlays and LK properties applied.

* Save I2C and SPI device addresses

[,shell]
----
adb shell "grep ^ /sys/bus/i2c/devices/*/name" > stock-i2c.txt
adb shell "grep ^ /sys/bus/spi/devices/*/modalias" > stock-spi.txt
----

* Save `/proc/cmdline` for various details, such as panel driver in the downstream.
