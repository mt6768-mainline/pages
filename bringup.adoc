== U-Boot
It's better to port U-Boot first, since it will speed up iterations with `fastboot boot`. Note that U-Boot *CANNOT* boot stock Android.

* Clone https://github.com/mt6768-mainline/u-boot[U-Boot].
* Make sure you have an AArch64 GCC cross-compiler installed, such as `aarch64-linux-gnu-gcc`.
* Copy the `merlin` devicetree and adapt it for your device, stripping out everything except UART and USB.
* Run `make ARCH=arm CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc) merlin_defconfig` and replace the default DT name with your own.
* Run `make ARCH=arm CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc)` to build U-Boot.

=== Running as kernel
This is helpful because panel driver debugging might be tricky. Usually, Linux and U-Boot should work fine with and without stock LK bootloader.

* Run `magiskboot unpack boot.img` on stock boot image.
* Replace `kernel` file with `u-boot.bin`.
* Run `magiskboot repack boot.img uboot.img`
* Flash `uboot.img` to device `boot` partition.

=== Running as bootloader
This is preferred since U-Boot doesn't silently break your assumptions about enabled clocks and pinctrl. Generally, replacing LK with U-Boot is better after display bringup was done.

* Because most retail devices are fused, we will need to use preloader exploit. Make sure your preloader is 2023 or older (`wrap` mode), 2025 or older (`override` mode) and install https://github.com/R0rt1z2/lkpatcher[lkpatcher].
* Patch your stock `lk.img` backup to replace the `lk` payload with `u-boot.bin`:
+
[,shell]
----
python -m lkpatcher lk.img --replace-partition lk u-boot.bin --cert-bypass wrap -o uboot.img
----
* Flash `uboot.img` to device `lk` partition.
* Once it boots as LK, you can port display support.

== Linux Kernel
* Clone https://github.com/mt6768-mainline/linux[Linux].
* Make sure you have LLVM or GCC cross-compiler for AArch64.
* Make sure you've ported U-Boot first.
* Copy `merlin` DT, remove *all* i2c, spi and display-related nodes. Keep only UART, USB and simple framebuffer.
* Depending if LK or U-Boot framebuffer is used, address for simple framebuffer may differ. U-Boot framebuffer is usually displayed with `bdinfo` command. LK framebuffer is a reserved memory node.
* Configure the kernel:
+
[,shell]
----
make ARCH=arm64 LLVM=1 -j$(nproc) mt6768_defconfig
----
* Enable USB gadget and add `console=ttyGS0` to expose shell over USB if UART is not available.
* Build using `make ARCH=arm64 LLVM=1 -j$(nproc)` (or GCC)
* Once kernel is built, you will need initramfs. It can be busybox, buildroot or anything else.
* Boot the kernel over fastboot (replace the `--dtb` path with your own devicetree blob):
+
[,shell]
----
fastboot boot arch/arm64/boot/Image.gz rootfs.cpio.lz4 \
    --dtb arch/arm64/boot/dts/mediatek/mt6768-xiaomi-merlin-nt36672a-ktd3137.dtb \
    --header-version 2
----
* Once kernel boots, start adding supplies for CPU and CCI nodes (frequency scaling), GPU, display panel, i2c and spi devices, and so on. merlin DT should be a good reference for this.

== TF-A
There's no need to port it, since TF-A should be generic for all devices on the same platform. Note that you *CANNOT* boot stock LK with custom TF-A.

* Clone https://github.com/mt6768-mainline/arm-trusted-firmware[it].
* Build using `make PLAT=mt6768 DEBUG=1 bl31 -j$(nproc)`.
* Clone https://github.com/mt6768-mainline/atftools[atftools] and install https://github.com/R0rt1z2/lkpatcher[lkpatcher].
* Prepare an image:
+
[,shell]
----
pack-atf tee.img ../arm-trusted-firmware/build/mt6768/debug/bl31.bin atfsign.img
----
* Flash `atfsign.img` to `tee1` partition.
